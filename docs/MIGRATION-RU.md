# Перенос меню и прогресса

Исходная версия может продолжать работать во время подготовки Vercel. После перехода её данные и новые данные Supabase независимы: автоматической синхронизации нет.

## Готовый приватный SQL-файл

Для текущего меню можно подготовить отдельный `private-snapshot.sql` и передать владельцу вне публичного репозитория. После `supabase/setup.sql` вставь этот файл в Supabase SQL Editor и выполни его **до первого учебного входа** на Vercel.

Файл содержит меню и общую историю прогресса, но не PIN, ключи Supabase или старые сессии входа. Не публикуй его в GitHub. Импорт в уже инициализированную базу намеренно отклоняется (`target_not_empty`), чтобы не стереть новый прогресс.

## Повторный экспорт перед окончательным переходом

На компьютере с Node.js 24:

```sh
node scripts/export-legacy.mjs --url https://<старый-сайт> --out /private/path/snapshot.json
```

Скрипт спросит старый PIN скрытым вводом. Он сохранит JSON и SQL рядом, выполнит только вход, чтение каталога и выход. Каталог и прогресс на старом сайте не меняются. Повторный экспорт полезен, если сотрудники продолжали обучение после предыдущего снимка.

Вариант импорта через терминал:

1. Создай локальный `.env` по `.env.example`; введи URL и серверный ключ Supabase.
2. Выполни `npm run import:legacy -- /private/path/snapshot.json`.
3. Секреты и снимок должны остаться вне Git.

Неопубликованные черновики и оригинальные файлы из старого R2 не входят в этот снимок. Они остаются на прежнем сайте и требуют отдельного переноса. Изображения исходного меню уже включены в репозиторий и попадут в Vercel автоматически.
